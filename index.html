Case Study
Investment Management · Agentic AI · AWS Bedrock

How I replaced a week-long manual process
with a zero-touchpoint agentic analyst.

The Client

T. Rowe Price is one of the world's largest active asset managers — $1.8 trillion in AUM across 8,000+ retirement plans, 2.3 million plan participants, and clients in 50+ countries. Their investment analysts are among the most experienced in the industry: each one covers a book of advisor-submitted portfolios, conducting deep research before making allocation recommendations.

The problem was that this research process — rigorous, structured, and highly repeatable — was consuming an enormous amount of analyst time that could have been spent on judgment rather than data retrieval.

The Problem

When an advisor at T. Rowe Price submits a portfolio for review, an analyst takes over. Before they can make a single recommendation, they need to do five things manually:

  1. Research the portfolio manager — their track record, strategy philosophy, recent commentary, and public bio — using web search and internal sources.
  2. Pull historical portfolio data from multiple third-party fund and strategy APIs with inconsistent schemas and rate limits.
  3. Analyze how the current allocation compares to historical positioning — drift, concentration shifts, risk changes.
  4. Model comparison — benchmark the portfolio against relevant models on risk metrics, margins, and performance across time horizons.
  5. Write a structured analyst report consolidating all of the above into a recommendation document.

Each full portfolio review took one analyst one week — end to end. With 500+ portfolios submitted per month, this was a scaling wall. The team couldn't take on more volume without adding headcount, and analysts were spending the majority of their time on retrieval and formatting, not on the actual judgment work they were hired for.

A simple automation wouldn't cut it. The data lived across fragmented APIs. The web research required real-time search and synthesis. The historical analysis required contextual retrieval, not keyword lookup. And the final report required coherent narrative generation — not template fill-in. This needed an agent that could reason across sources, not just retrieve from one.

The Architecture

I designed a 6-skill Strands agent on AWS Bedrock AgentCore. The core design principle was explicit skill decomposition — each unit of work that a human analyst does becomes a discrete, testable, independently-observable agent skill. This makes the system auditable, debuggable, and extensible without touching the orchestration layer.

01
Data Ingestion Lambda
Calls third-party fund and strategy APIs, normalizes inconsistent schemas, and stages structured data for downstream skills. Isolated as a Lambda so API failures are contained and retryable without restarting the full agent run.
02
Web Research Skill
Runs targeted web searches to build a profile of the portfolio manager — bio, investment philosophy, recent public commentary, and track record signals. Produces a structured summary the downstream skills can reference.
03
Historical Research Skill
Retrieves the relevant historical data for the specific portfolio request — not a broad dump, but contextually filtered by the advisor's current portfolio composition and the review period in scope.
04
Allocation Review Skill
Analyzes historical vs. current portfolio allocation — identifying drift, concentration changes, sector shifts, and positioning changes that an analyst would flag in a review.
05
Model Comparison Skill
Benchmarks the portfolio against relevant models across multiple dimensions: risk metrics, return margins, volatility, and historical alignment — the quantitative backbone of the analyst recommendation.
06
Writeup Generator Skill
Pulls outputs from all five upstream skills and generates the final structured analyst report — narrative, data tables, and recommendation summary — in the format analysts and advisors expect.

I chose Strands on AWS Bedrock AgentCore over LangGraph here for a specific reason: the client's infrastructure was already AWS-native, and AgentCore gave us production-grade skill isolation, IAM-controlled tool access, and native observability with CloudWatch — without needing to build and maintain an orchestration layer ourselves. The tradeoff was less flexibility in custom control flow, which was acceptable because the workflow here is largely linear with well-defined hand-offs between skills.

Failure recovery was designed at the skill level — each skill has explicit retry logic and a failure state that the agent can report on without halting the full run. This meant partial outputs (e.g., web research succeeded but one API failed) were still usable and flagged rather than silently dropped.

Takeaway

The right architecture for an agentic system isn't the most sophisticated one — it's the one where every skill does exactly one job, fails loudly when it can't, and hands off a clean output the next skill can trust. Decompose first. Orchestrate second.
